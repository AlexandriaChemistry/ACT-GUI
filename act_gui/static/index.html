          How the login works
          
        
          
          
            
            
          • 1The interface starts the program ssh of this computer, which uses your own keys and settings. It never asks for a password and keeps none.
            • 
            
          • 2So the login has to work without a question: ssh user@server in a terminal must log you in without typing anything. Set up a key for the server for that. If the server wants a password or a code every time, open one connection in a terminal with connection sharing (ControlMaster in the configuration of ssh) and leave it open.
            • 
            
          • 3Jobs are submitted with sbatch from the working directory, each in a directory of its own.
            • 
            
          • 4Test the login logs in once, to see that the directory is there and that the server has Slurm.
            • 
            
          • 5The interface logs in as seldom as it can: once to send a job, once in a while to ask for the state of all jobs together, and once to fetch the results of a job that ended. After a login that did not work it does not try again by itself.
            • 
          
          
          
          Nothing is ever removed on the cluster: the directory of a job stays there until you remove it yourself.
